---
name: scene-uid-generation
description: how to add a missing uid:// to a .tscn's [gd_scene] header via headless Godot, and how the plain --editor pass differs from what scripts get
type: reference
---

`.gd` scripts get their `uid://` via a `.uid` sidecar file, and a plain
`--headless --editor --path <project> --quit` pass (see
`feedback_uid_sidecar_files.md`) reliably writes those, because script UID
registration happens during global-class scanning regardless of whether the
script is ever opened.

**Scenes are different.** A `.tscn`'s uid lives inline in its own
`[gd_scene ... uid="uid://..."]` header, and the plain editor-scan pass above
does **not** backfill it for existing scenes that were hand-authored or
generated by an out-of-editor tool — confirmed by several pre-existing scenes
in this repo (`world/props/boulder.tscn`, `world/props/tree_oak.tscn`, most of
`ui/notebook/**/*.tscn`) sitting without a `uid=` for a long time despite
repeated headless editor passes. The uid only gets embedded when the scene
resource is actually *saved* through a codepath that has Godot's `ResourceUID`
cache populated (normally: opening + Ctrl+S in the real editor GUI).

**Reliable headless-only method:** run a `SceneTree`-extending script via
`godot --headless --path <project> -s <script>.gd`, that does
`ResourceSaver.save(load(path), path)` for the target scene(s) — but do this
**together with `--editor`** on the same invocation
(`--headless --editor --path <project> -s <script>.gd --quit`), not a bare
`-s` run alone. A bare `-s` run (no `--editor`) does execute the resave and
returns `err=0`, but the `ResourceUID` cache isn't populated in that context:
it silently *strips* any existing `uid=` from that scene's own `ext_resource`
lines (e.g. dropped the script's `uid="uid://bcluyhxxyvfbn"` reference) while
still failing to add a `uid=` to the `[gd_scene]` header itself — a
same-effort false-negative that's easy to mistake for success (exit code 0,
looks fine on a quick `head`). Always diff the resaved file against git before
trusting it. With `--editor` present, the same `ResourceSaver.save()` call
correctly assigns a fresh `uid://` to the header AND preserves existing
`ext_resource uid=` values.

After resaving a leaf scene this way, any OTHER scene that references it via
`ext_resource` (e.g. `world.tscn` referencing `boulder.tscn`) needs its own
`ext_resource` line hand-edited to add the matching `uid="..."` — resaving the
leaf scene does not retroactively update every referencing scene's ext_resource
lines. Copy the exact uid string the leaf scene ended up with.

Note: `ResourceSaver.save()` on a scene may also drop the `load_steps=N` count
hint from the `[gd_scene]` header. This is cosmetic (Godot recomputes it on
the next real editor save) and not worth restoring by hand.

See also `feedback_uid_sidecar_files.md` for the script-file version of this
problem, and [[worldprop-placeholder-visual-convention]] for the scenes used
as the worked example here.
